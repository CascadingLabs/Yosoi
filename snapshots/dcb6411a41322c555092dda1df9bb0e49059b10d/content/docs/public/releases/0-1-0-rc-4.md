# Yosoi 0.1.0-rc.4

## Summary

Yosoi 0.1.0-rc.4 corrects the test HTTP server teardown that stalled Windows
free-threaded release checks. The request outcomes and sibling cancellation
assertions had completed; the fixture then waited indefinitely for client
transports to close. The fixture now closes remaining clients explicitly and
bounds its shutdown wait. No SDK API or cancellation implementation changes.

## Improvements

Rust CI pairs verified source hashes and timestamps with compiled target
archives to improve reuse of linked test binaries. Compiler-result caching and
parallel doctests retain all correctness and publication gates. Timing targets
remain under measurement; this candidate does not claim they have been met.

## Chromium containers

The candidate includes the existing generic headless and headful Chromium/CDP
images adapted into Yosoi. Headless supports Linux AMD64 and ARM64; headful
supports Linux AMD64. These browser images contain no Yosoi application code.
They retain non-root operation, Chromium sandboxing, independent profiles, and
an opt-in headful viewer. See the
[container instructions](https://github.com/CascadingLabs/Yosoi/blob/v0.1.0-rc.4/docker/chromium/README.md).

## Known limitations

RC SDK packages are distributed through GitHub release assets. Final-beta
Crates.io and PyPI publication remains gated on resolving browser dependency
distribution and clean registry-installed tests. Container smoke checks remain
separate from full browser/controller certification and hardware GPU testing.
Frontend work is separate from this candidate.

## Upgrading

Rust metadata uses `0.1.0-rc.4`; Python metadata uses `0.1.0rc4`.
Container tags are `ghcr.io/cascadinglabs/chromium-cdp:headless-0.1.0-rc.4`
and `ghcr.io/cascadinglabs/chromium-cdp:headful-0.1.0-rc.4`.
On Linux, use host networking for the loopback CDP listeners. There is no SDK
API migration from rc.3, and earlier candidate tags remain immutable.
