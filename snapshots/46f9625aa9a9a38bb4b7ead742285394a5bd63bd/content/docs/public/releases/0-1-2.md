# Yosoi 0.1.2

## Summary

Yosoi 0.1.2 embeds its patched Chromiumoxide controller and generated CDP bindings inside the Yosoi crate. Applications continue to depend on `yosoi`; the SDK no longer depends on separately published Yosoi Chromiumoxide forks.

Release CD now tests the built wheels before uploading them and finalizes publication after successful registry uploads. This removes the duplicate post-upload installation matrix that raced with PyPI index propagation.

## Highlights

### Internal browser implementation

The controller and CDP bindings are private modules distributed in the Yosoi package. Their license notices, patch provenance, protocol inputs, and generation verification remain with the source. The controller base, protocol revision, browser security settings, and behavior are unchanged by this packaging move.

### Faster release completion

All 30 pre-publication wheel installation checks remain, including Python 3.15 and free-threaded imports that verify the GIL stays disabled. GitHub assets, Chromium images, and versioned docs wait on successful PyPI upload and, for final releases, successful crates.io publication. They no longer wait for a second installation matrix against PyPI.

## Upgrading

Update the Rust dependency or Python package to `yosoi` version `0.1.2`. The public SDK and `#[derive(Contract)]` syntax remain unchanged. Rust still automatically installs the independently versioned `yosoi-contracts-derive` helper; Rust requires custom derives to be implemented in a separate procedural-macro crate.

Previously published browser fork packages remain available for older Yosoi releases. This release does not upgrade or certify a new Chromium/controller/protocol tuple; the existing Chromium/CDP baseline and beta limitations still apply.
