# Yosoi 0.1.0-rc.3

## Summary

Yosoi 0.1.0-rc.3 adds versioned headless and headful Chromium/CDP containers
and exercises the faster release pipeline. This candidate retains the full
installed-wheel test matrix while sharing compatible Python wheel builds.

## Highlights

### Chromium containers

The existing VoidCrawl browser images move into Yosoi with generic names and
Yosoi runtime paths. Headless supports Linux AMD64 and ARM64; headful supports
Linux AMD64 with separate Sway outputs and an opt-in local viewer. These are
browser services, without Yosoi application code. See the
[container instructions](https://github.com/CascadingLabs/Yosoi/blob/v0.1.0-rc.3/docker/chromium/README.md)
and [the container change](https://github.com/CascadingLabs/Yosoi/pull/128).

Containers preserve non-root operation, Chromium sandboxing, and site/process
isolation. They use regular Debian Stable Chromium 154.0.8037.92. Admission of
the Debian 13 distribution preserves the reviewed exact version and age checks;
full browser/controller certification remains separate from container smoke tests.

### Shared Python wheels

Ordinary CPython 3.12–3.15 share a stable ABI wheel. Free-threaded 3.14 keeps
its dedicated ABI wheel, and free-threaded 3.15 uses its stable ABI wheel.
All six interpreter variants still run installed-artifact checks on every
release platform. Native builds and browser image builds run concurrently;
publication reuses tested artifacts rather than compiling again.

## Known limitations

RC Python/Rust packages are distributed through GitHub release assets.
Crates.io and PyPI publication for the final beta still require resolving the
browser dependency distribution strategy and clean registry-installed tests.
Container smoke evidence does not certify stealth, hardware GPUs, or the
complete Yosoi browser/controller tuple. SDK attachment requires the existing
verifiable local executable and loopback boundary.

## Upgrading

Rust metadata uses `0.1.0-rc.3`; Python metadata uses `0.1.0rc3`.
Container tags are `ghcr.io/cascadinglabs/chromium-cdp:headless-0.1.0-rc.3`
and `ghcr.io/cascadinglabs/chromium-cdp:headful-0.1.0-rc.3`.
Use consecutive CDP ports from `CDP_PORT_BASE` in place of the Alpha image's
individual `CDP_PORT_1`/`CDP_PORT_2` overrides. Set `BROWSER_COUNT` explicitly;
these generic browser images do not infer Yosoi worker-pool sizes.
