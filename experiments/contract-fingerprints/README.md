# Contract-scoped product fingerprint spike (CAS-632)

Discover a Product extraction recipe on QScrape's JavaScript-rendered mug and
lamp, freeze it, then try the notebook, tote, catch-all and bottle without further
AI discovery. This is an experimental Rust executable, not a new public SDK API.

## What happened

The frozen recipe correctly extracted and independently verified **three of four
held-out products**. The sold-out catch-all was rejected: its button adds a
`disabled` attribute, bringing root and ID-component similarity to 0.846154,
below the fixed per-component threshold of 0.85. Aggregate similarity remained
0.942308. The threshold was not adjusted after seeing this case.

A separate **post-hoc seed-sensitivity experiment** reused the same captures,
features, weights, recipe and threshold:

| Reference products | Accepted and oracle-verified products, including seeds |
| --- | --- |
| Lamp + mug | 5/6 |
| Mug + sold-out catch-all | 6/6 |
| Sold-out catch-all alone | 1/6 |

Two modes provide coverage of both states. The matcher does not learn that
`disabled` is irrelevant. These post-hoc results are not fresh held-out evidence.
Two identical-layout references also do not provide two independent structural
families. None of these counts establishes a calibrated probability of reuse.

## Contract and evidence

The real Beta `Contract` derive defines six required String fields: ID, name,
price, color, material and stock. Ordinary Contract extraction and validation
check complete evidence and exactly-one cardinality. Application validation
checks requested identity, nonblank text, checked integer USD cents conversion,
and explicit available/unavailable stock. A separate fixture oracle checks the
actual values; successful parsing alone cannot establish that a value is correct.

Only rendered DOM is used. Each product-detail element is the selected root;
its fields select evidence within it. The ID is an attribute on that root.
There is no whole-document fingerprint, accessibility evidence, embedding,
clustering or assignment algorithm.

Manual discovery inspected **only obj-001 and obj-002** before freezing. Selectors
are pinned from their actual DOM, not generated by a new AI-discovery service.
The live REST fixture oracle was fetched only after freezing, and is never read
by the locator, fingerprint, reference selection or runtime validator.

Two existing SDK boundaries required private adapters:

* `Work::observe` exposes ready rendered HTML, while the public DOM constructor
  accepts versioned JSON. The collector normalizes that immutable HTML using
  scripting-enabled html5ever, assigns snapshot-local IDs, constructs a real
  `Document::rendered_dom`, and validates it with the SDK parser. IDs are not CDP
  backend-node IDs. Collection uses an owned Session, event-driven heading
  readiness, explicit Work release and Session close, with the browser sandbox.
* The Beta CSS subset has no sibling/positional/label predicate, and scoped
  selectors exclude the root itself. The frozen recipe selects fact values
  through SDK locators, joins them to their Material/Color label in the same
  parent, and attaches the root's ID evidence to its product lineage. The
  resulting Findings retain actual DOM coordinates and go through the normal
  Contract validator. This is explicit experiment-local composition, not native
  support for arbitrary nested Contracts.

A plain Request initially captured the Astro loading shell before hydration.
Those captures are not seed references or successful product extractions. The
collector was corrected to wait for `main h1` before observing the page. Captured
DOM descendant text is not a general visibility guarantee.

## Fingerprint and matching policy

`selected-dom-paths-v1-depth3` stores exact, sorted sparse strings, without
sketching or random projections. Features contain element tags and attribute
**names**, selected-root-relative field paths, and descendant paths up to three
element levels. Text, attribute values, CSS class values, document IDs, snapshot
node IDs and sibling order do not enter the structural signature.

For each corresponding root/field, weighted Jaccard gives relation features
weight 2 and descendant features weight 1. The parent aggregates root weight 2
and each required field weight 1. Full evidence coverage, aggregate similarity
at least 0.85, and every component similarity at least 0.85 are required. A
candidate may match **either** reference. An unsupported profile/schema or empty
comparison abstains/errors; it does not match vacuously.

Field correspondence is supplied by the contract, not inferred by name similarity.
There are no optional fields in this first experiment. The ID selects the same
node as the root, so their structural features duplicate evidence; this is a
known limitation of the baseline, not an independent signal. Root content beyond
three element levels is not represented by root descendant paths, although each
selected field retains its own root-relative path and local signature.

Fingerprints include a profile and schema checksum; references bind them to an
archived source and portable recipe/Plan. SHA-256 checksums establish exact record
identity, not semantic correctness. `frozen.json` records the unchanged plan
checksum `70885aa5a6e83b1dfee5b6a7edbbfe0e4d7211f8197d2c3f42f0dba1d0bf50f8`.

## Controls and limitations

| Mutation of the mug snapshot | Observed result |
| --- | --- |
| Remove price element | Missing coverage; reuse rejected; Contract also rejects it |
| Replace price with `$999.00` | Similarity 1.0 and runtime-valid; independent oracle rejects |
| Reorder Material and Color fact components | Correct extraction retained |
| Make a second element match the price selector | Cardinality rejected |
| Change copy wrapper tag from `section` to `aside` | Structural policy rejects |
| Move a price-looking decoy outside the selected root | Correct extraction retained |

This tiny, single-template corpus provides one observed false rejection among
four held-out pages. It does not measure cross-site false-match rates. The
wrong-price control demonstrates why structural acceptance is not correctness.
A rejected product is recorded for rediscovery; no fallback AI discovery is
implemented. Exact English labels and stock prose are specific to this fixture.

## Archive and offline reproduction

The checked-in `fixtures/evidence/` contains real SDK Archive records and payloads for the
sources, frozen references, oracle, report and sensitivity experiment. Fingerprint
attachments are versioned **JSON Documents stored through `Archive`**, rather
than a new built-in Archive record kind. Standard Archive integrity and owner-private permission checks remain
in force. Because Git does not retain private permission modes, replay stages the
immutable bytes into an owner-private temporary store before opening Archive;
source fixtures are never rewritten. Symlinks and special files are rejected. `*.ref.json` files identify those records; readable JSON reports are
review copies. Replay uses authoritative archived payloads and recomputes seed
fingerprints, comparisons, extraction, oracle checks and controls. Original
unreferenced loading-shell payloads are retained as capture history.

From the repository root, with no browser or network needed:

```sh
CARGO_BUILD_JOBS=1 RAYON_NUM_THREADS=1 cargo run --locked -p yosoi \
  --example contract_fingerprint_spike -- replay experiments/contract-fingerprints/fixtures/evidence

CARGO_BUILD_JOBS=1 RAYON_NUM_THREADS=1 cargo test --locked -p yosoi \
  --example contract_fingerprint_spike -- --test-threads=1
```

The example is registered with `test = true`, so its offline tests also run in
the existing hosted Rust suites. No tests require the live shop.

## Repeat the live experiment

Set `CHROME` to an admitted regular Stable executable; no launch-policy changes
or sandbox exceptions are needed. The recorded run used regular Google Chrome
156.0.8078.47 and SDK 0.4.0 on Linux. Use a fresh output directory, since freeze
refuses to overwrite an existing reference or run after held-out captures.

```sh
export CHROME=/path/to/regular/stable/chrome
CARGO_BUILD_JOBS=1 cargo build --locked -p yosoi --features browser \
  --example contract_fingerprint_spike
spike_bin=target/debug/examples/contract_fingerprint_spike
spike_output=.generated/product-fingerprints

"$spike_bin" capture "$spike_output" obj-001
"$spike_bin" capture "$spike_output" obj-002
"$spike_bin" freeze "$spike_output"
for id in obj-003 obj-004 obj-005 obj-006; do
  "$spike_bin" capture "$spike_output" "$id" || break
done
curl --fail --silent --show-error https://qscrape.dev/api/eshop/products/ \
  -o "$spike_output/oracle-response.json"
jq '[.data[] | {id,name,price_cents:.price,color,material,
  stock:(if .stock == 0 then "Unavailable" else {Available:.stock} end)}]' \
  "$spike_output/oracle-response.json" > "$spike_output/oracle.json"
"$spike_bin" evaluate "$spike_output" "$spike_output/oracle.json"
"$spike_bin" sensitivity "$spike_output"
"$spike_bin" replay "$spike_output"
```

A collection-level zero in this fixture oracle is translated to its independently
observed unavailable state. The DOM runtime retains the distinction between
unavailability and an explicitly stated available quantity of zero.

## Measured cost and next decision

A complete uncompressed exact fingerprint is **2,627 bytes**, or 2,645 bytes for
the sold-out variant. This is the attachment including profile/schema identity
and every component's sparse features, not the much larger source archive. We
have not demonstrated a few-hundred-byte encoding.

One local unoptimized run evaluated six products plus six controls in 106,372 us,
including source Archive reads but excluding browser capture, seed reconstruction
and the oracle write. A separate full offline replay including seed sensitivity
took 0.35 s wall time and 26,640 KiB peak process RSS (`/usr/bin/time -v`). These
are single debug runs, not steady-state latency, allocation measurements, release
benchmarks, per-fingerprint RAM figures or large-index throughput claims.

The next experiment should decide which attribute names represent structure
versus transient state, eliminate duplicate root/ID evidence, and evaluate that
new profile on **new** variants. Broader layout families and hard negatives are
needed before adopting matching thresholds or building an index. SimHash,
weighted MinHash, optional/nested Contract composition and clustering remain
separate follow-ups; the current result does not select a production algorithm.
