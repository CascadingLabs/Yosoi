## Measured behaviour (books.toscrape, frozen)

- 51,294 B document → 3,250 B across both reductions (~16×), 79 index entries.
- 20 product cards cost **2 entries** (region + exemplar); all 20 reachable via `expand`
  with `stable=True`.
- `inspect` on member 1 returns the *Tipping the Velvet* record.

## Measured behaviour (`repeat_scale`, generated)

| Rows | Document | Index entries | Index bytes | Ratio | Build |
| --- | --- | --- | --- | --- | --- |
| 1,000 | 169,270 B | 17 | 960 B | 176× | 27 ms |
| 10,000 | 1,698,283 B | **17** | 969 B | 1,753× | 181 ms |

Same entry count at 10× the rows — the row count reaches the index only as the `×10000` in one
summary and the element census. All 10,000 members come back through `expand` with
`stable=True` (durable `id`), swept in 4 pages of 2,500. Cost is linear: measured exponent
0.99–1.17 across doublings from 1k to 40k rows.

The artifact is generated by `tests/boss_fights/generators/repeat_table.py` and pinned by
`generated_sha256` in the manifest — 1.7 MB is not committable, but "generated" does not mean
"unpinned". Peak memory is explicitly **not** gated (`[limits] peak_memory = false`): lxml's
tree lives on the C heap where tracemalloc cannot see it and maxrss cannot attribute it.

## Measured behaviour (`reference_stability`, generated)

One page, captured seven ways: unchanged plus six edits. What survives:

| Edit | Identities lost | Region identity |
| --- | --- | --- |
| captured again, unchanged | 0 | same |
| `section_above` — insert near top of `<body>` | **0** | same |
| `row_inserted` — record mid-list | 0 | same |
| `rows_reordered` | exemplar's only | same |
| `column_added` — every row gains a cell | row-derived | **changes** |
| `prose_reworded` | text-keyed only | same |
| `class_restyled` | class-anchored only | same |

`section_above` is the row that justifies the work: a root-absolute address space loses every
reference below the insertion, and this loses none.

Identity coverage — how much of a page is durably addressable at all:

| Workload | With `ref_id` | Refused |
| --- | --- | --- |
| books.toscrape (frozen, real) | 59/79 (74%) | 19 positional tails, 1 unkeyed member |
| repeat_scale (10,000 rows) | 17/17 (100%) | — |
| reference_stability (generated) | 19/21 (90%) | 2 positional tails |

Anchor tiers used on books: 32 class, 13 first-attribute, 12 tag, 2 id. A quarter of a real page
gets no identity, and that number is the finding — not a gap to paper over by loosening the
rule.

## Measured behaviour (`wikipedia_web_scraping`, frozen real revision)

The negative control, and the reason rendering is a separate stage:

| Stage | Size |
| --- | --- |
| Pinned article revision 1367063064 | 163,164 B |
| Structured index (correct, and unusable as an overview) | 84,239 B / 1,038 entries |
| Rendered overview at a 900-token budget | 3,439 B / 852 tokens / 45 entries shown |

All 17 `h2`/`h3` section headings survive into the overview, the footer states "993 omitted and
still inspectable by [ordinal]", and prose the overview does not carry is one `inspect` away.
Token counts come from a declared estimator (`estimate/chars-per-token-4`) — this package has no
provider tokenizer, so every token gate is paired with a byte gate, and a renderer refuses any
tokenizer whose id disagrees with the policy it was handed.

## Measured behaviour (`multi_hop`, generated)

Three nesting levels — 4 departments × 5 teams × 6 rows = **120 leaf records in 20 index
entries**, addresses composing four segments deep, every one carrying an identity.

A five-hop investigation (overview → expand departments → inspect one → expand rows → inspect
one leaf) reads **under 6 KB of an 18 KB document**. That is the claim worth gating: per-call
bounds with no session bound just split the same payload across five messages.

`rebind` is what makes depth navigable. The pruner descends into ONE exemplar per region, so the
index describes department 1 only; `inspector.rebind(ref, ['id=dept-3', 'id=team-3-1'])` carries
that route onto a branch nothing ever indexed, and resolves it before returning.

## Invariants — do not break these

Each one exists because breaking it produced a real failure, not because it reads well.

1. **Location is not identity, and `RegionRef` is location.** Two of its four fields are the
   snapshot id and the artifact digest, so it is unequal across captures by construction. The
   comparable value is `IndexEntry.ref_id`, derived from what the page provides and nothing the
   capture provides. Do not "fix" a ref so it compares across snapshots — that would make an
   exact reference into an approximate one.
2. **Addresses are segmented, never bare XPath.** `parse_address` / `format_address` in
   `index/addressing.py` are the only places that know the grammar. A bare absolute path
   is a *valid* address (one segment) but must not be minted for anything inside a repeat
   region — that is precisely what rots on scroll.
3. **Identity needs all three: anchored, stable, positional-free.** Anchored means rooted at a
   document-unique key rather than `/html/body/…`; positional-free means no `[n]` step anywhere,
    *including below the anchor*. Weaken any one and `ref_id` starts meaning "probably the same
   thing", which is the failure this package exists to avoid. `html`/`head`/`body` are excluded
   from the tag-anchor tier — unique in every document, so they identify nothing.
4. **Positional fallback is declared, never silent.** No key → `&ordinal=N` and
   `is_stable` goes False. Never emit an ordinal dressed as a key.
5. **Keys are uniqueness-checked within their group.** A key matching two rows is not an
   address. `assign_member_keys` enforces this; don't bypass it.
6. **Coverage is required on regions, forbidden elsewhere.** Enforced by a
   `PrunedFragment` validator and carried into `IndexEntry`. A partial region must never
   be indistinguishable from a complete one.
7. **Never strip classes, ids, or style attributes.** Measured worst representation in
   NEXT-EVAL (F1 0.10, 91% hallucination), and they are what Yosoi selectors are made of.
   If you see a "slim the HTML" TODO, it is wrong — delete it.
8. **The pruner and the inspector share one definition of shape and key** (`html_tree.py`).
   A second implementation is how an address stops resolving to what it was minted for.
9. **Pruners are pure**: no I/O, no browser, no model, no mutation of the source tree.
10. **Canonical artifacts are immutable.** Detail is always re-derived from bytes, never
   from a summary.
11. **The `eval` mark on this tier does not mean non-deterministic.** Boss fights are
   offline and provider-free. They must never fetch a live site.
12. **Ground truth never contains an emitted `RegionRef`.** Fixtures state evidence by an
    independent XPath oracle; `HtmlWorkload.entries_reaching` maps oracle → emitted address.

## Traps already paid for

- **`id()` on lxml elements is NOT stable.** lxml mints a fresh Python proxy per access and
  frees it when the last reference drops; CPython reuses the address immediately. A
  `dict[int, str]` signature memo therefore returns *another element's* shape. This merged
  two differently-shaped `<div>`s into a bogus `×2` region and swallowed the entire
  20-product grid, silently. `SignatureCache` now stores `(element, digest)` to pin the id.
  **Any new cache keyed on an lxml element must do the same.**
- **Per-element key uniqueness checking is O(n²)** and dies on the table this exists for.
  Count once for the whole group.
- **`<head>`-only declaration indexing loses real findings.** books.toscrape loads jQuery
  over plain `http://` from the end of `<body>`. Partition by the spec's *metadata content*
  category instead — `METADATA_CONTENT` in `html_tree.py`.
- **Ranking regions above headings starves the routing layer.** On the 1,038-entry Wikipedia
  article the 81 regions consumed the whole 900-token budget and all 17 section headings were
  dropped. Headings are few and are the page's own table of contents; they go first.
- **A member key below a rebind is branch-specific.** `id=team-1-1` exists only inside
  department 1, so swapping the outer key alone yields a reference that fails deep in
  resolution. `rebind` requires a key per remaining member segment and says so.
- **Event handlers live on structure, not metadata.** `<body onload>` is indexed by the
  body pruner (it emits the structure root deliberately), not the declaration pruner.

Adding a workload: `manifest.toml` (identity, capabilities, budgets, prediction, failure)
+ `ground_truth.toml` (oracles) + `artifacts/` + `test_<modality>_<workload>.py`. Test
module names must be globally unique. Write the prediction **before** running the pruner.
For a workload too large to commit, drop `artifacts/`, pin `generator` + `generated_sha256`
in the manifest, and build through the `generated_html_workload` fixture instead.

## Open decisions

- `MAX_BODY_DEPTH = 12` and `MIN_RUN = 2` are class constants folded into the pruner
  version, not `PruningPolicy` fields — modality-specific dials in a shared policy felt
  wrong. Revisit if a second modality wants the same dial.
- The declaration label uses the author's *first attribute* as the key. Degrades to a
  still-correct but less scannable label if an author writes `content=` before `name=`.
  No case found in the corpus yet; worth watching.
- `InspectionBudget.max_items` is currently only meaningful for `expand`; `inspect` always
  returns exactly one node.
