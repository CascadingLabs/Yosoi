# CAS-306 Direct HTTP orchestration

`capture_direct_http` is the concrete bundle-last entry point. Success is an owning `DirectHttpCapture` containing the bundle, bounded response facts, optional source-representation facts, and execution identity; its `into_parts` returns every component without loss. It executes explicit redirect traversal under the attempt deadline, consumes the content-coded response body, classifies and decodes retained representation bytes, constructs requested results, and delegates receipt/observation/acquisition/capture/bundle construction to `AcquisitionLifecycle::finalize`.

The API never claims wire bytes. The currently requested minimal network family is therefore an explicit `web_capture.direct_http.network_bytes_unavailable` result: wreq exposes response semantics and a content-coded body, not a reviewed serialized wire exchange.

Source bytes are retained for complete and truncated outcomes. Unsupported or unknown classifications retain those bytes under `RetainAndReport` and produce no Unicode payload. `FailAttempt` returns a typed construction failure carrying redacted response facts, resolution, retained body outcome, and classification/decoding facts; no bundle is published. Body decoding/header/disconnect/deadline/cancellation/limit outcomes finalize as incomplete captures when a lifecycle and resolution exist.

## Exact failure boundary

A request/redirect failure before a final response currently returns `DirectHttpCaptureError::Transport(DirectHttpFailure)`. That existing non-lossy value owns the stopped lifecycle, partial resolution when known, final unread redirect response when one exists, primary typed transport error, and secondary termination failure. Existing public models cannot finalize this into a `WebCapture`: `LifecycleFinalizationInput` requires a `CaptureResolution`, while pre-resolution failures deliberately represent that fact as absent. The orchestrator does not substitute the requested URL or otherwise invent resolution evidence.

A failure inside `consume_response_body` returns its typed source. Such errors are lifecycle-invariant failures rather than ordinary body terminals; ordinary malformed coding, disconnect, limits, deadline, cancellation, sink write/commit failure, and unavailable body states are values and continue through finalization. A crate-test-only full-orchestration seam injects a `PayloadSink` and can force the terminal lifecycle offset invariant. Tests use it to prove sink failures publish an unavailable family with no payload, while `DirectHttpCaptureError::Body` owns redacted response facts, resolution, lifecycle, execution identity, the typed primary error, and explicit consumed/unpublishable evidence state. This seam is not exported by the library.

## Determinism and fixtures

The `_at` entry point injects wall-clock start time; monotonic transport time and the single absolute deadline remain real. Production independently samples source generation, decoded generation, and finish times. `capture_direct_http_with_clock` injects all four ordered timestamps for deterministic tests; finalization rejects artifact times outside the observation window. Local fixture tests invoke the public orchestrator through the reusable `tests/support/direct_http_fixture` service, with explicit cancellation and joins for listener and connection tasks. They verify four formats, exact bundle payload lookup, unavailable network truth, fixed capture identity, timestamp error precedence, and truncated-prefix publication. All fixture traffic is loopback-only. HTTPS full-chain coverage lives at the crate unit-test boundary: a crate-internal client seam installs the embedded fixture CA in wreq and runs the public-equivalent orchestrator. The stable public API exposes neither wreq nor custom trust configuration, and TLS verification is not weakened.

Full declaration, classification, and decoding observations are preserved in a typed `SourceRepresentation` derived-evidence artifact. Its compact canonical JSON payload contains no decoded text, has its own schema/digest/extent, derives from the exact final source artifact, and is validated through `CaptureBundle`. `DirectHttpCapture::source_facts` remains a convenient in-memory view rather than the durability boundary.

Decoded UTF-8 output is a distinct `decoded_source` result and `DecodedSourceArtifactRef`; it is never rewrapped as source. The field is retention-policy-derived and therefore does not extend `WebArtifactRequestSet`. `decoded_source` is part of the current pre-release Web Capture v1 shape. There are no production consumers, so obsolete development shapes are not backward-read: code, fixtures, and documentation advance together under the v1 name until the first public compatibility commitment.

`SourceRepresentationEvidence` preserves media declaration, classification basis/candidates/disagreement/extent, and decoding status/encoding/basis/conflicts/replacements/truncation without duplicating decoded payload bytes. A caller with only canonical Web Capture v1 metadata and typed payload pairs can locate the artifact, validate its size/digest/final-source lineage, and parse the facts offline. `replay_source_facts` remains an equivalence-check path that recomputes the in-memory facts from retained source and response observations.

The checked-in direct HTTP corpus inventory is exercised by loopback tests: declared HTML (including a JavaScript shell), generic XML, Atom XML, XHTML, JSON and problem+json, malformed JSON, UTF-8 and Windows-1252 plain text, declared and undeclared empty bodies, non-2xx HTML/JSON, binary unknown input, unsupported CSV/text-json, BOM conflicts, UTF-16LE, HTML meta charset, XML declarations, and JSON BOM. Assertions use typed classification variants, fixed source bytes and SHA-256 constants, decoded lineage/media/encoding, explicit no-decoded outcomes, fixed capture/activity/operation identities, URLs/status, and exhaustive artifact request/result states. Content-coding, limits, disconnects, redirects, cancellation, TLS, and policy behavior remain in their dedicated corpus modules.
