# Yosoi 0.2.0

## Summary

Yosoi 0.2.0 adds a Rust and Python browser SDK over the existing private browser
runtime. Short tasks can use managed Requests and Flows; stateful workflows can
retain a Session and borrow exclusive Work leases. Structured outcomes preserve
failed checks, uncertain effects and cleanup failures.

## Highlights

### Browser ownership and reusable Flows

Rust and Python share one execution engine. Compose typed actions into a Flow,
select policy at invocation, or borrow a caller-owned Work lease. Managed calls
clean up their own resources; borrowed calls retain caller ownership and cannot
elevate the Session's permissions.

Timeout inputs are integer milliseconds, with the nearest explicit scope taking
precedence. Recoverable failures and local child cancellation default to
Continue; select Stop when subsequent actions depend on success. Inspect the
outcome, and use `require_completed()` for a strict success path.

### Typed assertions and bounded confirmation

Immediate assertion groups evaluate local predicates over one canonical
Contract observation. Scoped Until checks provide bounded confirmation without
repeating the triggering action. Reports distinguish rejected checks, predicate
errors, cancellation and uncertain effects. Saved recipes retain descriptors;
executable predicates and cancellation bindings must be rebound before use.

### JavaScript snapshots and captured evidence

Explicitly permitted JavaScript can use bounded construction-time file
snapshots and local module graphs. Selected exports are read as JSON-compatible
values. Rust Archive records and Views expose bounded captured evidence and
inspection, with provenance checks and capture-bound cursors.

## Known limitations

The Python beta exposes the initial Session tab and one borrowed Work lease.
Explicit tab creation, Watcher streams and the Rust Archive/View facade are
outside this Python surface. Synchronous Python predicates must remain short
and pure; cancellation cannot forcibly stop a running Python function or undo
dispatched browser effects.

Chrome or Chromium must be installed separately, using a supported regular
Stable distribution with its sandbox enabled. Local and hosted browser
regressions do not establish a complete browser/controller/CDP certification.
Firefox/BiDi, remote attachment, distributed placement, durable browser
resumption, isolated JavaScript worlds and package/network module imports are
outside this beta scope. Stronger Archive durability and replay guarantees
remain deferred.

The release configuration targets five native platforms and CPython 3.12–3.15,
including free-threaded 3.14 and 3.15. Publication requires the existing
release-profile artifact and installed-wheel matrix; configuration alone is not
platform certification.

## Upgrading

Upgrade Rust and Python consumers together to the selected 0.2.0 artifacts.
Python still requires `>=3.12,<3.16` and Pydantic `>=2.14,<3`. Ordinary Python
uses the `cp312-abi3` wheel family; free-threaded 3.14 uses `cp314-cp314t`, and
free-threaded 3.15 uses `cp315-abi3.abi3t`.

The Rust SDK pins independently versioned `yosoi-contracts-derive` 0.1.2.
Release packaging publishes that helper before the SDK; consumers do not need
a separate browser-provider crate.

Policy JSON now includes `default_action_timeout_ms` and Flow continuation
settings. Preserve those fields when storing new policies. Current effective
policy identities use version 7; historical Archive records retain their own
recorded identity instead of being relabeled as current.

Use explicit Stop policies for dependent workflows such as checkout. A returned
Flow outcome can contain failures under Continue and should not be treated as
confirmation of the application's result.
