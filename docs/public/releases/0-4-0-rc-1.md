# Yosoi 0.4.0-rc.1

## Summary

Yosoi 0.4.0-rc.1 introduces Surfaces: bounded views of documents and video that callers can explore before choosing what to read or do. Rust, Python and the CLI share the underlying index, reference checks and evidence model. Surface outcomes can be saved in portable files and inspected without the original session.

This is a prerelease for testing and review, not the final 0.4.0 release. It includes the merged Surface, Archive, networking, optional-browser and Contract changes. Discovery integration and the separate live-recording experiment are not part of this candidate.

## Highlights

### Explore evidence a piece at a time

Start with an overview, search literal text, then inspect a returned reference. Continuations keep replies bounded without treating a partial page as the whole source. Video adds timeline navigation, requested frames and crops. Start with the [Surface walkthrough](../concepts/surfaces.md).

The live web adapter lets an agent act through the CLI after attaching, acquiring control and validating current evidence. An action is confirmed only when its declared postcondition is observed.

### Carry an outcome to another process

Enable archive retention to keep observations, operation receipts and incomplete outcomes. Export a self-contained `.yosoi` file, move it to another directory, and reload it without the original Archive. Offline replay reads evidence; a live rerun opens fresh sources and resolves targets again. Saved evidence never grants permission to act. See [Archiving a surface](../concepts/archiving-a-surface.md).

### Choose a browser and its network route

Chrome/CDP remains the default. The optional native BiDi controller supports qualified Firefox and Moli configurations, with explicit capability limits and no silent fallback. [Choosing a browser](../concepts/choosing-a-browser.md) explains engine selection.

Requests and owned browser Sessions can opt into IPv4 or IPv6, a local source address, and authenticated HTTP, HTTPS or SOCKS proxies. Destination TLS remains between the client and site. A proxy controls its own destination DNS and egress; selecting a family or source address controls the connection to that proxy. See [Network routing](../concepts/network-routing.md).

## Upgrading

The built-in USD-only `Money` and `Currency` types have been removed. Keep extracted prices as `String` or `str`, then interpret them in application code. Python Contracts continue to use ordinary Pydantic types, constraints and custom validators.

This is a breaking change: `Money` imports, `money.usd` runtime schemas, saved `money_usd` values and money-specific rejection payloads are no longer supported. There is no automatic archive migration. Keep 0.3.0 available to read existing money-bearing records and export the application data you need before upgrading.

Rust callers that construct `UntilScope` with a struct literal must supply its new optional `protocol` field. Existing serialized CDP scopes remain readable. Surface references remain bound to their original observation and cannot be reused as permits in a new session.

## Install: try the candidate

Python packages use the normalized version `0.4.0rc1`. Rust source and GitHub assets use `0.4.0-rc.1`. The RC pipeline publishes Python distributions and prebuilt CLI assets; it does not publish Rust crates to crates.io.

### uv

In a Python project:

```sh
uv add 'yosoi==0.4.0rc1'
uv run python -c 'import yosoi; print(yosoi.__version__)'
```

For the standalone CLI:

```sh
uv tool install 'yosoi-cli==0.4.0rc1'
yosoi --version
```

Use `--force` with `uv tool install` if replacing an existing CLI installation. The SDK requires Python 3.12 through 3.15; supported wheel variants include free-threaded Python 3.14 and 3.15.

### Cargo

Clone the candidate source, then add its SDK to your application:

```sh
git clone --branch v0.4.0-rc.1 --depth 1 https://github.com/CascadingLabs/Yosoi.git yosoi-rc
export YOSOI_REPO_ROOT="$(pwd)/yosoi-rc"
```

From your Rust application directory:

```sh
cargo add yosoi --path "$YOSOI_REPO_ROOT/crates/yosoi" --features browser-bidi,surface-connections
cargo add tokio --features macros,rt
```

Rust 1.99 or newer is required. The source path keeps the SDK and its workspace dependencies on the same candidate. A document-only Surface needs neither browser feature; enable the features used by the workflow you want to review.

## Review the new workflows

1. Run the local document example in [Surfaces](../concepts/surfaces.md), then inspect and paginate its evidence.
2. Save and reload a portable outcome with [Archiving a surface](../concepts/archiving-a-surface.md).
3. Use the synthetic QScrape cart task in the Surface walkthrough to inspect a confirmed action receipt.
4. Try a supported Firefox or Moli capture from [Choosing a browser](../concepts/choosing-a-browser.md).

Browser programs need installed compatible engines. The live Surface web adapter separately needs ChromeDriver and regular Chrome or Chromium. Video decoding needs FFmpeg and FFprobe. Local Archive storage requires Unix.

Video is read-only and does not provide OCR, transcription, audio capture or live streaming. The Surface web transport is separate from the native BiDi controller. Firefox and Moli do not provide every Chrome capability; consult the engine guide before requesting accessibility or network evidence.
